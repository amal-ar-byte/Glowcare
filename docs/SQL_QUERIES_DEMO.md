## 1. DDL – Data Definition Language

### 1.1 CREATE TABLE – Users Table

```sql
CREATE TABLE users (
    user_id       INT AUTO_INCREMENT PRIMARY KEY,
    full_name     VARCHAR(100)  NOT NULL,
    email         VARCHAR(150)  NOT NULL UNIQUE,
    password_hash VARCHAR(255)  NOT NULL,
    phone         VARCHAR(20)   DEFAULT NULL,
    date_of_birth DATE          DEFAULT NULL,
    gender        ENUM('Male','Female','Other','Prefer not to say') DEFAULT NULL,
    role          ENUM('user','admin') NOT NULL DEFAULT 'user',
    profile_image VARCHAR(255)  DEFAULT NULL,
    created_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_users_email (email),
    INDEX idx_users_role (role)
) ENGINE=InnoDB;
```

> **Concepts demonstrated:** AUTO_INCREMENT, PRIMARY KEY, UNIQUE constraint, ENUM data type, DEFAULT values, CURRENT_TIMESTAMP, ON UPDATE trigger, INDEX creation, InnoDB engine.

### 1.2 CREATE TABLE – Products Table (with CHECK constraint)

```sql
CREATE TABLE products (
    product_id      INT AUTO_INCREMENT PRIMARY KEY,
    name            VARCHAR(200)  NOT NULL,
    category_id     INT           NOT NULL,
    price           DECIMAL(10,2) NOT NULL CHECK (price >= 0),
    description     TEXT          DEFAULT NULL,
    skin_type       ENUM('oily','dry','combination','normal','sensitive','all') NOT NULL DEFAULT 'all',
    is_active       TINYINT(1)    NOT NULL DEFAULT 1,
    created_at      DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_product_category
        FOREIGN KEY (category_id) REFERENCES categories(category_id)
        ON DELETE RESTRICT ON UPDATE CASCADE,
    INDEX idx_product_category (category_id),
    INDEX idx_product_skin_type (skin_type)
) ENGINE=InnoDB;
```

> **Concepts demonstrated:** DECIMAL precision, CHECK constraint, FOREIGN KEY with ON DELETE RESTRICT and ON UPDATE CASCADE, named constraints.

### 1.3 ALTER TABLE – Add a column

```sql
-- Example: Adding a 'brand' column to the products table
ALTER TABLE products
ADD COLUMN brand VARCHAR(100) DEFAULT NULL AFTER name;
```

> **Concepts demonstrated:** ALTER TABLE, ADD COLUMN, column placement with AFTER.

### 1.4 DROP TABLE

```sql
-- Example: Drop a table (use with caution)
DROP TABLE IF EXISTS wishlists;
```

> **Concepts demonstrated:** DROP TABLE with IF EXISTS safety check.

## 2. DML – Data Manipulation Language

### 2.1 INSERT – Register a New User

```sql
INSERT INTO users (full_name, email, password_hash, phone, date_of_birth, gender)
VALUES ('Jane Doe', 'jane@example.com', '$2y$10$hashed_password_here', '9876543210', '1998-05-15', 'Female');
```

> **Description:** Inserts a new user record. The `password_hash` contains a bcrypt hash generated by PHP's `password_hash()` function. The `role` defaults to `'user'` and timestamps are auto-generated.

### 2.2 INSERT – Add a New Product

```sql
INSERT INTO products (name, category_id, price, description, ingredients, usage_instructions, precautions, skin_type, image_path)
VALUES (
    'Hydrating Gel Cleanser',
    1,
    450.00,
    'A gentle gel cleanser that removes impurities without stripping moisture.',
    'Water, Glycerin, Sodium Hyaluronate, Aloe Vera Extract',
    'Apply a small amount to wet face. Massage gently and rinse with water.',
    'Avoid contact with eyes. Discontinue use if irritation occurs.',
    'dry',
    '/images/products/hydrating-cleanser.jpg'
);
```

### 2.3 INSERT – Add Multiple Categories (Bulk Insert)

```sql
INSERT INTO categories (category_name, description) VALUES
    ('Cleanser', 'Face wash and cleansing products'),
    ('Toner', 'Balancing and hydrating toners'),
    ('Serum', 'Concentrated treatment serums'),
    ('Moisturiser', 'Hydrating creams and lotions'),
    ('Sunscreen', 'UV protection products'),
    ('Exfoliator', 'Physical and chemical exfoliants'),
    ('Eye Cream', 'Under-eye treatment products'),
    ('Face Mask', 'Sheet masks and wash-off masks');
```

> **Concepts demonstrated:** Multi-row INSERT for seed data.

### 2.4 UPDATE – Update User Profile

```sql
UPDATE users
SET full_name = 'Jane Smith',
    phone = '9123456789',
    profile_image = '/images/profiles/jane-smith.jpg',
    updated_at = CURRENT_TIMESTAMP
WHERE user_id = 1;
```

> **Description:** Updates specific fields for a user. The `WHERE` clause ensures only the target user is modified.

### 2.5 UPDATE – Deactivate a Product (Soft Delete)

```sql
UPDATE products
SET is_active = 0,
    updated_at = CURRENT_TIMESTAMP
WHERE product_id = 5;
```

> **Description:** Soft-deletes a product by setting `is_active = 0` instead of permanently removing the record. This preserves historical data integrity for routine steps that reference this product.

### 2.6 DELETE – Remove a Product from Wishlist

```sql
DELETE FROM wishlists
WHERE user_id = 1
  AND product_id = 3;
```

> **Description:** Removes a specific product from a user's wishlist. The composite condition ensures only the correct record is deleted.

### 2.7 DELETE – Delete a Routine and Its Steps (Cascade)

```sql
DELETE FROM routines
WHERE routine_id = 7
  AND user_id = 1;
```

> **Description:** Deletes a routine owned by user 1. Due to `ON DELETE CASCADE` on the foreign key, all associated `routine_steps` records are automatically deleted.

## 3. SELECT Queries

### 3.1 SELECT with WHERE – Find User by Email

```sql
SELECT user_id, full_name, email, password_hash, role
FROM users
WHERE email = 'jane@example.com';
```

> **Description:** Used during login to retrieve user credentials for password verification.

### 3.2 SELECT with ORDER BY – List Products by Price

```sql
SELECT product_id, name, price, skin_type
FROM products
WHERE is_active = 1
ORDER BY price ASC;
```

> **Description:** Retrieves active products sorted by price (lowest first). Change `ASC` to `DESC` for highest first.

### 3.3 SELECT with DISTINCT – List All Skin Types in Assessments

```sql
SELECT DISTINCT skin_type
FROM skin_assessments
ORDER BY skin_type ASC;
```

> **Description:** Returns unique skin types that have been assessed, useful for analytics.

### 3.4 SELECT with LIMIT and OFFSET – Pagination

```sql
SELECT p.product_id, p.name, p.price, p.skin_type, c.category_name
FROM products p
JOIN categories c ON p.category_id = c.category_id
WHERE p.is_active = 1
ORDER BY p.created_at DESC
LIMIT 12 OFFSET 0;
```

> **Description:** Retrieves the first page of 12 products. For page 2, use `OFFSET 12`; for page 3, use `OFFSET 24`, etc.

### 3.5 SELECT with LIKE – Search Products by Name

```sql
SELECT product_id, name, price, skin_type
FROM products
WHERE is_active = 1
  AND name LIKE '%cleanser%'
ORDER BY name ASC;
```

> **Description:** Case-insensitive keyword search for products containing "cleanser" in the name.

### 3.6 SELECT with Multiple WHERE Conditions – Filter Products

```sql
SELECT product_id, name, price, skin_type
FROM products
WHERE is_active = 1
  AND category_id = 1
  AND skin_type IN ('oily', 'all')
  AND price BETWEEN 200 AND 1000
ORDER BY price ASC;
```

> **Description:** Filters active products by category, skin type compatibility, and price range.

## 4. JOIN Queries

### 4.1 INNER JOIN – Products with Category Names

```sql
SELECT
    p.product_id,
    p.name AS product_name,
    c.category_name,
    p.price,
    p.skin_type,
    p.description
FROM products p
INNER JOIN categories c ON p.category_id = c.category_id
WHERE p.is_active = 1
ORDER BY c.category_name, p.name;
```

> **Description:** Joins products with their category names. Only products with a matching category are returned (INNER JOIN excludes orphan products).

### 4.2 LEFT JOIN – Users with Their Latest Assessment

```sql
SELECT
    u.user_id,
    u.full_name,
    u.email,
    u.created_at AS member_since,
    sa.skin_type,
    sa.concerns,
    sa.assessment_date
FROM users u
LEFT JOIN skin_assessments sa ON u.user_id = sa.user_id
    AND sa.assessment_date = (
        SELECT MAX(sa2.assessment_date)
        FROM skin_assessments sa2
        WHERE sa2.user_id = u.user_id
    )
WHERE u.role = 'user'
ORDER BY u.created_at DESC;
```

> **Description:** LEFT JOIN ensures all users appear, even if they haven't taken an assessment (their skin_type will be NULL). The subquery ensures only the latest assessment is joined.

### 4.3 INNER JOIN – Routine Steps with Product Details

```sql
SELECT
    rs.step_id,
    rs.step_name,
    rs.step_order,
    rs.is_completed,
    rs.completed_date,
    p.name AS product_name,
    p.price AS product_price,
    p.image_path
FROM routine_steps rs
LEFT JOIN products p ON rs.product_id = p.product_id
WHERE rs.routine_id = 3
ORDER BY rs.step_order ASC;
```

> **Description:** Retrieves all steps of a specific routine with optional product details. LEFT JOIN is used because `product_id` can be NULL.

### 4.4 Multi-Table JOIN – User Progress with Routine Details

```sql
SELECT
    pl.log_id,
    pl.log_date,
    pl.completion_status,
    pl.skin_feeling,
    pl.notes,
    rs.step_name,
    r.routine_name,
    r.routine_type
FROM progress_logs pl
LEFT JOIN routine_steps rs ON pl.routine_step_id = rs.step_id
LEFT JOIN routines r ON rs.routine_id = r.routine_id
WHERE pl.user_id = 1
ORDER BY pl.log_date DESC, pl.created_at DESC;
```

> **Description:** Joins progress logs with routine steps and routines to provide a comprehensive progress history view.

### 4.5 JOIN – User's Wishlist with Product and Category Details

```sql
SELECT
    w.wishlist_id,
    w.date_added,
    p.product_id,
    p.name AS product_name,
    p.price,
    p.skin_type,
    p.image_path,
    c.category_name
FROM wishlists w
INNER JOIN products p ON w.product_id = p.product_id
INNER JOIN categories c ON p.category_id = c.category_id
WHERE w.user_id = 1
  AND p.is_active = 1
ORDER BY w.date_added DESC;
```

> **Description:** Retrieves a user's complete wishlist with product and category details. Only active products are shown.

## 5. Aggregate Functions

### 5.1 COUNT – Total Number of Registered Users

```sql
SELECT COUNT(*) AS total_users
FROM users
WHERE role = 'user';
```

> **Description:** Counts all users with the 'user' role (excludes admins).

### 5.2 COUNT – Products per Category

```sql
SELECT
    c.category_name,
    COUNT(p.product_id) AS product_count
FROM categories c
LEFT JOIN products p ON c.category_id = p.category_id AND p.is_active = 1
GROUP BY c.category_id, c.category_name
ORDER BY product_count DESC;
```

> **Description:** Counts active products in each category. LEFT JOIN ensures categories with zero products are still listed.

### 5.3 AVG – Average Product Price

```sql
SELECT
    AVG(price) AS avg_price,
    ROUND(AVG(price), 2) AS avg_price_rounded
FROM products
WHERE is_active = 1;
```

> **Description:** Calculates the average price of all active products.

### 5.4 MIN and MAX – Price Range

```sql
SELECT
    MIN(price) AS cheapest_product_price,
    MAX(price) AS most_expensive_price
FROM products
WHERE is_active = 1;
```

> **Description:** Retrieves the minimum and maximum product prices for display on filter sliders.

### 5.5 COUNT with CASE – Assessment Statistics

```sql
SELECT
    COUNT(*) AS total_assessments,
    SUM(CASE WHEN skin_type = 'oily' THEN 1 ELSE 0 END) AS oily_count,
    SUM(CASE WHEN skin_type = 'dry' THEN 1 ELSE 0 END) AS dry_count,
    SUM(CASE WHEN skin_type = 'combination' THEN 1 ELSE 0 END) AS combination_count,
    SUM(CASE WHEN skin_type = 'normal' THEN 1 ELSE 0 END) AS normal_count,
    SUM(CASE WHEN skin_type = 'sensitive' THEN 1 ELSE 0 END) AS sensitive_count
FROM skin_assessments;
```

> **Description:** Provides a breakdown of assessment results by skin type for the admin statistics dashboard.

## 6. GROUP BY and HAVING

### 6.1 GROUP BY – Routines per User

```sql
SELECT
    u.user_id,
    u.full_name,
    COUNT(r.routine_id) AS routine_count
FROM users u
LEFT JOIN routines r ON u.user_id = r.user_id
WHERE u.role = 'user'
GROUP BY u.user_id, u.full_name
ORDER BY routine_count DESC;
```

> **Description:** Shows how many routines each user has created.

### 6.2 GROUP BY with HAVING – Users with More Than 5 Progress Logs

```sql
SELECT
    u.user_id,
    u.full_name,
    COUNT(pl.log_id) AS total_logs
FROM users u
INNER JOIN progress_logs pl ON u.user_id = pl.user_id
GROUP BY u.user_id, u.full_name
HAVING COUNT(pl.log_id) > 5
ORDER BY total_logs DESC;
```

> **Description:** Identifies highly engaged users who have logged progress more than 5 times. The `HAVING` clause filters groups after aggregation.

### 6.3 GROUP BY – Weekly Progress Summary

```sql
SELECT
    user_id,
    YEARWEEK(log_date, 1) AS year_week,
    COUNT(*) AS total_logs,
    SUM(CASE WHEN completion_status = 'completed' THEN 1 ELSE 0 END) AS completed_count,
    SUM(CASE WHEN completion_status = 'skipped' THEN 1 ELSE 0 END) AS skipped_count,
    SUM(CASE WHEN completion_status = 'partial' THEN 1 ELSE 0 END) AS partial_count,
    MIN(log_date) AS week_start,
    MAX(log_date) AS week_end
FROM progress_logs
WHERE user_id = 1
GROUP BY user_id, YEARWEEK(log_date, 1)
ORDER BY year_week DESC;
```

> **Description:** Groups progress logs by week and provides completion/skip counts. This query is the basis of the `vw_weekly_progress` view.

### 6.4 GROUP BY with HAVING – Categories with Expensive Products

```sql
SELECT
    c.category_name,
    COUNT(p.product_id) AS product_count,
    AVG(p.price) AS avg_price,
    MAX(p.price) AS max_price
FROM categories c
INNER JOIN products p ON c.category_id = p.category_id
WHERE p.is_active = 1
GROUP BY c.category_id, c.category_name
HAVING AVG(p.price) > 500
ORDER BY avg_price DESC;
```

> **Description:** Finds categories where the average product price exceeds ₹500. Useful for pricing analysis.

## 7. Subqueries

### 7.1 Scalar Subquery – User's Latest Skin Type

```sql
SELECT
    user_id,
    full_name,
    (
        SELECT skin_type
        FROM skin_assessments sa
        WHERE sa.user_id = u.user_id
        ORDER BY assessment_date DESC
        LIMIT 1
    ) AS current_skin_type
FROM users u
WHERE role = 'user';
```

> **Description:** A correlated scalar subquery that retrieves each user's most recent skin type in a single query.

### 7.2 IN Subquery – Products in a User's Wishlist

```sql
SELECT product_id, name, price, skin_type
FROM products
WHERE product_id IN (
    SELECT product_id
    FROM wishlists
    WHERE user_id = 1
)
AND is_active = 1
ORDER BY name;
```

> **Description:** Uses an `IN` subquery to find all active products that exist in a specific user's wishlist.

### 7.3 NOT IN Subquery – Products NOT in Wishlist

```sql
SELECT product_id, name, price, skin_type
FROM products
WHERE is_active = 1
  AND product_id NOT IN (
    SELECT product_id
    FROM wishlists
    WHERE user_id = 1
  )
ORDER BY name;
```

> **Description:** Retrieves products that the user has NOT yet wishlisted. Useful for "You might like" recommendations.

### 7.4 Correlated Subquery – Users with Their Assessment Count

```sql
SELECT
    u.user_id,
    u.full_name,
    u.email,
    (
        SELECT COUNT(*)
        FROM skin_assessments sa
        WHERE sa.user_id = u.user_id
    ) AS assessment_count
FROM users u
WHERE u.role = 'user'
ORDER BY assessment_count DESC;
```

> **Description:** A correlated subquery that counts each user's assessments. Executes the inner query once per user row.

### 7.5 EXISTS Subquery – Users Who Have Taken an Assessment

```sql
SELECT user_id, full_name, email
FROM users u
WHERE EXISTS (
    SELECT 1
    FROM skin_assessments sa
    WHERE sa.user_id = u.user_id
)
AND role = 'user';
```

> **Description:** Returns only users who have at least one assessment record. `EXISTS` is generally more efficient than `IN` for large datasets.

### 7.6 Subquery in FROM (Derived Table) – Top Wishlist Products

```sql
SELECT
    p.product_id,
    p.name,
    p.price,
    wc.wishlist_count
FROM products p
INNER JOIN (
    SELECT product_id, COUNT(*) AS wishlist_count
    FROM wishlists
    GROUP BY product_id
    ORDER BY wishlist_count DESC
    LIMIT 10
) wc ON p.product_id = wc.product_id
ORDER BY wc.wishlist_count DESC;
```

> **Description:** Uses a derived table (subquery in FROM) to find the top 10 most wishlisted products with their wishlist counts.

## 8. Prepared Statements (PHP PDO)

All database queries in the GlowCare PHP backend use **PDO (PHP Data Objects)** with prepared statements to prevent SQL injection attacks.

### 8.1 Database Connection

```php
<?php
// config/database.php

class Database {
    private $host = 'localhost';
    private $db_name = 'glowcare';
    private $username = 'root';
    private $password = '';
    private $conn;

    public function getConnection() {
        $this->conn = null;
        try {
            $this->conn = new PDO(
                "mysql:host={$this->host};dbname={$this->db_name};charset=utf8mb4",
                $this->username,
                $this->password,
                [
                    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
                    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
                    PDO::ATTR_EMULATE_PREPARES   => false
                ]
            );
        } catch (PDOException $e) {
            error_log("Database connection failed: " . $e->getMessage());
            die(json_encode(["error" => "Database connection failed"]));
        }
        return $this->conn;
    }
}
```

> **Concepts demonstrated:** PDO connection with charset, error mode, fetch mode, and native prepared statements (`EMULATE_PREPARES = false`).

### 8.2 Prepared SELECT – User Login

```php
<?php
// Fetch user by email for login verification
$stmt = $conn->prepare("
    SELECT user_id, full_name, email, password_hash, role
    FROM users
    WHERE email = :email
");
$stmt->bindParam(':email', $email, PDO::PARAM_STR);
$stmt->execute();
$user = $stmt->fetch();

if ($user && password_verify($password, $user['password_hash'])) {
    // Login successful
    session_start();
    session_regenerate_id(true);
    $_SESSION['user_id'] = $user['user_id'];
    $_SESSION['role']    = $user['role'];
    echo json_encode(["success" => true, "user" => $user]);
} else {
    // Login failed
    http_response_code(401);
    echo json_encode(["error" => "Invalid credentials"]);
}
```

> **Concepts demonstrated:** Named parameter binding (`:email`), `PDO::PARAM_STR`, `password_verify()`, session management.

### 8.3 Prepared INSERT – Save Skin Assessment

```php
<?php
// Save a new skin assessment
$stmt = $conn->prepare("
    INSERT INTO skin_assessments
        (user_id, skin_type, oily_feeling, dry_tight, easily_irritated, concerns)
    VALUES
        (:user_id, :skin_type, :oily_feeling, :dry_tight, :easily_irritated, :concerns)
");

$stmt->execute([
    ':user_id'          => $_SESSION['user_id'],
    ':skin_type'        => $determined_skin_type,
    ':oily_feeling'     => $data['oily_feeling'],
    ':dry_tight'        => $data['dry_tight'],
    ':easily_irritated' => $data['easily_irritated'],
    ':concerns'         => implode(',', $data['concerns'])
]);

$assessment_id = $conn->lastInsertId();
echo json_encode([
    "assessment_id" => $assessment_id,
    "skin_type"     => $determined_skin_type
]);
```

> **Concepts demonstrated:** Prepared INSERT with array parameter binding, `lastInsertId()` to retrieve the auto-generated primary key.

### 8.4 Prepared UPDATE – Update Product

```php
<?php
// Admin: Update an existing product
$stmt = $conn->prepare("
    UPDATE products
    SET name = :name,
        category_id = :category_id,
        price = :price,

$rows_affected = $stmt->rowCount();
echo json_encode(["updated" => $rows_affected > 0]);
```

> **Concepts demonstrated:** Prepared UPDATE, `rowCount()` to verify the operation affected a row.

### 8.5 Prepared DELETE – Remove from Wishlist

```php
<?php
// Remove a product from user's wishlist
$stmt = $conn->prepare("
    DELETE FROM wishlists
    WHERE user_id = :user_id
      AND product_id = :product_id
");

$stmt->execute([
    ':user_id'    => $_SESSION['user_id'],
    ':product_id' => $product_id
]);

if ($stmt->rowCount() > 0) {
    echo json_encode(["message" => "Product removed from wishlist"]);
} else {
    http_response_code(404);
    echo json_encode(["error" => "Product not found in wishlist"]);
}
```

> **Concepts demonstrated:** Prepared DELETE with ownership validation, error handling for non-existent records.

### 8.6 Prepared Statement with JOIN – Fetch Routine with Steps

```php
<?php
// Fetch a user's routines with their steps and linked product names
$stmt = $conn->prepare("
    SELECT
        r.routine_id,
        r.routine_name,
        r.routine_type,
        rs.step_id,
        rs.step_name,
        rs.step_order,
        rs.is_completed,
        rs.completed_date,
        p.name AS product_name,
        p.image_path AS product_image
    FROM routines r
    LEFT JOIN routine_steps rs ON r.routine_id = rs.routine_id
    LEFT JOIN products p ON rs.product_id = p.product_id
    WHERE r.user_id = :user_id
    ORDER BY r.routine_type, r.routine_name, rs.step_order
");

$stmt->execute([':user_id' => $_SESSION['user_id']]);
$results = $stmt->fetchAll();
echo json_encode($results);
```

> **Concepts demonstrated:** Prepared statement with multi-table JOIN, fetchAll() for retrieving all result rows.

### 8.7 Transaction – Create Routine with Steps

```php
<?php
// Create a routine and its steps atomically
try {
    $conn->beginTransaction();

    // 1. Insert the routine
    $stmt = $conn->prepare("
        INSERT INTO routines (user_id, routine_name, routine_type)
        VALUES (:user_id, :name, :type)
    ");
    $stmt->execute([
        ':user_id' => $_SESSION['user_id'],
        ':name'    => $data['routine_name'],
        ':type'    => $data['routine_type']
    ]);
    $routine_id = $conn->lastInsertId();

    // 2. Insert each step
    $stepStmt = $conn->prepare("
        INSERT INTO routine_steps (routine_id, product_id, step_name, step_order)
        VALUES (:routine_id, :product_id, :step_name, :step_order)
    ");

    foreach ($data['steps'] as $index => $step) {
        $stepStmt->execute([
            ':routine_id' => $routine_id,
            ':product_id' => $step['product_id'] ?? null,
            ':step_name'  => $step['step_name'],
            ':step_order' => $index + 1
        ]);
    }

    $conn->commit();
    echo json_encode([
        "routine_id" => $routine_id,
        "message"    => "Routine created with " . count($data['steps']) . " steps"
    ]);

} catch (Exception $e) {
    $conn->rollBack();
    http_response_code(500);
    echo json_encode(["error" => "Failed to create routine: " . $e->getMessage()]);
}
```

> **Concepts demonstrated:** Database transactions (`beginTransaction`, `commit`, `rollBack`), atomicity guarantee — if step insertion fails, the routine insertion is also rolled back.
